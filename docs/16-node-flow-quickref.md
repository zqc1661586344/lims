# LIMS 全流程 16 节点速查表

> 用途：从**任务委托提交**到**项目归档**完整走完一个委托的操作速查。
> 核心规则：**每个节点 = 到该节点页面「新增(委托ID=流程实例ID)」→ 保存 → 在该记录上「通过」→ 流程推进到下一节点。**

## 一、16 节点流转顺序（速查）

```
任务创建 → 合同评审 → 质控任务 → 采样调度 → 现场采样 → 样品接收
→ 任务分配 → 数据录入 → 数据复核 → 数据审核 → 报告编制 → 报告复核
→ 报告审核 → 报告签发 → 报告发放 → 项目归档 ✅
```

## 二、每个节点的标准操作（重复这套即可）

对除第 1 步外的节点 2~16：

```
① 到对应节点的业务页面 → 点「新增/新建」
② 填写业务数据（关键：委托ID 填「流程实例 id」，即王小二=8 那个数字）
③ 保存 → 列表出现这条记录
④ 在这条记录上点「通过」→ 弹「…通过，流程已推进」
⑤ 到「待办任务」页确认当前节点已变为下一节点
→ 循环到下一节点
```

> 最后一个节点「项目归档」点「通过」后，流程 `status` 会变为 `completed`，整个委托走完。

## 三、关键原则（务必记住）

1. **委托ID = 流程实例ID**：你建的那条委托在 `task_orders` 表的 `id`（如王小二=8）。所有业务节点页的「委托ID」都要填这个数字，填错(如 985)会导致「未找到该委托当前待办的任务」。
2. **先增后批**：每个节点必须先**在该节点页面录入业务数据**，再点**通过**。只去「待办任务」页点通过、而不在业务页面录入数据，会导致该节点没有业务记录（页面空白是正常的）。
3. **审批只推进指针**：「待办任务」页的「处理→通过」只把流程指针移到下一节点，**不会自动生成**业务记录。
4. **业务记录 id ≠ 流程任务 id**：页面里的记录 id 是业务表主键；流程推进用的是 `process_tasks` 里的任务 id（后端已自动按委托ID解析，前端无需关心）。

## 四、验证流程是否正确推进（可选，用命令）

```bash
# 查看所有流程实例当前停在哪一步
docker exec -it $(docker ps -qf name=postgres) psql -U lims -d lims -c \
  "SELECT id, current_node, status FROM process_instances ORDER BY id DESC;"
```

- `current_node` = 当前停留节点（如 `node_data_entry`）
- `status` = `running`（进行中）或 `completed`（已归档完成）
